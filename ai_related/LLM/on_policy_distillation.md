# On-Policy Distillation

**OPD 可以先理解成：让学生自己做题，再让老师针对学生实际写出的过程提供指导。** 学生根据这些指导更新参数，然后重新做下一批题。

已经熟悉 SFT 和强化学习的话，理解 OPD 主要需要弄清三件事：训练用的回答是谁生成的，老师提供什么信息，以及这些信息怎样变成 loss。下面先走完一次训练，再展开两种 loss；之后讨论错误轨迹中的学习价值和实际执行方式。公式推导集中在附录，首次阅读可以跳过。

## 从老师先做题到学生先做题

假设我们想让一个小模型学习大模型的解题能力，称它们为 Student 和 Teacher。

最容易想到的办法是：**让 Teacher 先回答一批问题，把“问题 + 老师答案”保存下来，再对 Student 做 SFT。** 训练时，给学生老师答案的前半段，让它预测老师接下来写的 token。这就是很熟悉的老师答案 SFT。

例如题目是 `3 + 2 × 4`，老师的答案是：

> 先算 2 × 4 = 8，再算 3 + 8 = 11。

学生在训练中一直沿着这条正确的解题过程学习。但到自己生成时，学生可能写成：

> 先算 3 + 2 = 5，再算 5 × 4 = 20。

学生走到了另一条路径。原来的 SFT 数据主要告诉它“沿着老师的过程应该怎么继续”，未必覆盖“沿着学生自己容易写出的过程应该怎么继续”。

OPD 改变的是训练数据的产生方式：**先让 Student 回答问题，再让 Teacher 看 Student 已经写出的内容，给出每个位置上下一 token 的概率信息。** 这样，学生练习的就是自己当前确实会走到的情况。[Thinking Machines 的 OPD 介绍](https://thinkingmachines.ai/blog/on-policy-distillation/)用类似的思路解释了它与老师答案蒸馏的区别。

这里的“老师指导”具体指 token 概率信息，学生根据它构造训练信号。概率与正确性的区别，会在[错误轨迹中的学习价值](#错误轨迹中能学到什么)一节展开。

因此，**on-policy 中的 policy 就是 Student 当前的生成策略；on-policy 强调回答由当前 Student 自己生成。** 至于更新参数时用直接蒸馏还是策略梯度，是后面的另一个选择。

### 与老师答案 SFT 的区别不只在 loss

这里比较的是“用老师答案做普通 SFT”；SFT 的数据也可以来自人，不一定需要老师模型。

| 比较点                           | 老师答案 SFT           | 本文讨论的 OPD                |
| -------------------------------- | ---------------------- | ----------------------------- |
| 训练中沿着谁的前缀继续           | 老师答案的前缀         | 学生 rollout 的前缀           |
| 老师提供什么                     | 通常是确定的答案 token | 在学生前缀下的 token 概率     |
| 学生更新后，回答数据是否随之变化 | 固定数据集通常不变     | 后续重新 rollout 时随学生变化 |

**即使用同一种 loss，两者训练的上下文仍然不同。** 假设把老师答案 SFT 扩展为概率蒸馏，让两边都使用老师的完整概率分布，并采用同一种交叉熵：

$$
L(s)=-\sum_v q(v\mid s)\log p_\theta(v\mid s)
$$

这里 $p_\theta$ 是学生分布，$q$ 是老师分布，关键差异是上下文 $s$ 从哪里来：在老师轨迹上蒸馏时，$s$ 可能是“先算 2 × 4 = 8”；在学生轨迹上蒸馏时，$s$ 可能是“先算 3 + 2 = 5”。前者学习老师示范的路径，后者学习老师在学生实际所处状态下的行为。

所以，“使用 KL”或“使用策略梯度”都不是 OPD 的定义。**训练上下文由谁产生、老师提供什么监督、loss 怎样构造，是三个可以分别讨论的选择。** [verl 的 OPD 背景说明](https://verl.readthedocs.io/en/latest/algo/opd.html)

## 用一个例子走完一次 OPD 更新

先抓住这一点：**学生先生成一份回答；接着固定这份回答，让老师和学生分别计算概率；最后根据双方的概率计算 loss，更新学生。** 后面计算概率时，不会重新采样另一份回答。

下面用一个具体例子走完一次同步 OPD 更新。为了方便说明，把回答简化成四个 token；实际分词方式可能不同，概率也都是演示值。

### 第一步：学生先写出一份回答

假设输入是：

> 法国的首都是哪里？请用“首都是……”回答。

Student 正常调用生成接口，采样出：

```text
学生回答：首都是伦敦。
简化 token： [首都] [是] [伦敦] [。]
```

这一步就是 rollout。老师此时没有替学生选词，也没有给它标准答案。我们保存这份实际生成的回答，得到一条待训练的数据：

```text
问题 + 学生回答：
法国的首都是哪里？请用“首都是……”回答。 → 首都是伦敦。
```

它虽然答错了，仍然可以用于 OPD。接下来要做的，就是利用老师的信息调整学生的选择倾向。

### 第二步：固定这份回答让两个模型分别计算概率

把**同一份“问题 + 学生回答”**分别送进 Teacher 和 Student，做训练式的前向计算。

这一步与 SFT 的前向很像：输入序列已经固定，模型在各个位置预测下一个 token。我们分别获取老师和学生的预测结果，后面用它们一起构造 loss。这里要求的是两边使用相同的输入，不要求两次前向必须同时运行。

两个模型在每个位置看到的内容相同：

| 要预测的位置        | 两个模型在该位置能看到的前缀 | 学生当时实际选了什么 |
| ------------------- | ---------------------------- | -------------------- |
| 回答的第 1 个 token | 问题                         | 首都                 |
| 回答的第 2 个 token | 问题 + 首都                  | 是                   |
| 回答的第 3 个 token | 问题 + 首都是                | 伦敦                 |
| 回答的第 4 个 token | 问题 + 首都是伦敦            | 。                   |

重点看第 3 个位置。此时双方看到的都是：

> 问题 + 首都是

我们分别获取它们对下一个 token 的预测。假设得到：

| 下一个 token    | Teacher 概率 | Student 概率 |
| --------------- | -----------: | -----------: |
| 巴黎            |         0.60 |         0.20 |
| 里昂            |         0.30 |         0.10 |
| 伦敦            |         0.04 |         0.40 |
| 其余 token 合计 |         0.06 |         0.30 |

这张表就是训练信号的来源：**面对同一个前缀，学生更倾向于选“伦敦”，老师更倾向于选“巴黎”。**

虽然整份输入中已经有“伦敦”，但在预测它的那个位置，causal mask 会挡住它及后面的内容，模型只能看到“问题 + 首都是”。因此可以把序列整体输入，并行计算多个位置，不必真的按上表发四次请求。

Teacher 的这次前向不需要梯度；Student 的这次前向要保留计算图，因为稍后需要更新它的参数。

Student 在 rollout 时已经计算过概率，但通常没有保留训练计算图。因此这里重新前向，获取能够反向传播的概率；它读取的是固定回答，不会重新答一次题。

### 第三步：用双方的概率构造 loss

拿到概率后，有两种本文重点讨论的用法：

- **TA-OPD：** 比较老师 top-k 候选及剩余尾部上的概率分配，让学生的分布接近老师。
- **k1 + policy gradient：** 比较双方对学生实际选出的“伦敦”的概率，把差异形成的反馈用于策略梯度更新。

两种方法都使用这份固定回答，在有效回答 token 上计算并聚合 loss。下一章沿用这张概率表，分别展开具体计算。

### 第四步：反向传播然后进入下一批

有了 loss，执行熟悉的训练操作：

```text
loss.backward() → optimizer.step()
```

只更新 Student，Teacher 保持冻结。如果生成侧使用独立的 Student 实例，先把新权重同步过去，再让它生成下一批回答。

当前这份“首都是伦敦”的回答不会被自动改成“首都是巴黎”。改变的是学生参数，以及它下次生成时的概率分布。

与 SFT 对照，整轮训练的区别是：

```text
老师答案 SFT：
问题 + 老师答案 → Student 前向 → 对老师答案 token 做交叉熵 → 更新

OPD：
问题 → Student 先生成回答 → 固定这份“问题 + 学生回答”
                              ├─ Teacher 前向：提供监督信息，冻结参数
                              └─ Student 前向：计算带梯度的预测
                                       ↓
                         用双方的信息计算蒸馏 loss → 更新 Student
```

学生回答在这里提供的是“这次要学习哪些上下文，以及学生实际做了哪些选择”；它并没有因为被放进训练输入，就变成正确答案。更新的依据来自 Teacher 的监督信息。

换成 Coding Agent 时，也是这个过程，只是学生回答中穿插了工具调用和环境返回。Teacher 和 Student 评分时要看到相同的实际历史；工具返回通常作为后续预测的上下文，不作为模型应模仿生成的内容计算 loss。

## 老师的概率怎样变成训练信号

前面的训练流程在“构造 loss”处分成两条路：一条直接比较概率分布，另一条用采样 token 的概率形成策略梯度反馈。下面先讲 top-k 概率怎样对齐，再分别看 TA-OPD 和 k1 + PG。

### top-k：先对齐双方比较的候选

#### top-k=64 表示老师返回哪些信息

Teacher 在每个位置都会给整个词表的 token 分配概率。词表可能有二十多万项，如果把每个位置的整张概率表都传回来，开销很大。

top-k=64 的意思是：**在每个预测位置，只保留 Teacher 概率最高的 64 个 token 的 ID，以及对应概率。** 实现中通常传的是 logprob，表达的是同一份概率信息。

它不是让老师生成 64 个 token，也不是生成 64 份答案。它描述的是一个位置上的 64 个候选。不同位置，候选列表也可能不同。

#### 学生仍然输出整个词表再按相同 ID 取值

Student 没有变成一个只输出 64 类的模型。它通常仍然输出整个词表的 logits，再取出老师选中的那 64 个 token 对应的概率。

回到“首都是伦敦”的例子，仍然看前缀“问题 + 首都是”。把前面表中的“其余 token”展开成“柏林”和“罗马”，得到下面的五项简化词表。每项都假设为一个 token，概率仍是同一组演示值：

| token ID | token | Teacher 概率 | Student 概率 |
| -------- | ----- | -----------: | -----------: |
| 0        | 巴黎  |         0.60 |         0.20 |
| 1        | 里昂  |         0.30 |         0.10 |
| 2        | 伦敦  |         0.04 |         0.40 |
| 3        | 柏林  |         0.03 |         0.20 |
| 4        | 罗马  |         0.03 |         0.10 |

先把 k 缩小到 2。老师选出的 top-2 是“巴黎”和“里昂”：

```text
Teacher 返回的 ID：  [0, 1]
Teacher 对应概率：   [0.60, 0.30]

Student 按 [0, 1] 取值：
Student 对应概率：   [0.20, 0.10]
```

学生自己最喜欢“伦敦”，也不改变这里要取的 ID。**我们要比较的是双方对同一个 token 的判断，所以必须用老师的 ID 去取学生的概率。**

这里“老师先选、学生再取”说的是索引依赖：Student 计算整个词表的 logits 不需要提前知道老师选了谁，因此两边的前向可以先后执行，也可以在资源允许时并行执行；但按 ID 提取 Student 的 k 项结果，需要等 Teacher 给出 top-k ID。

代码上就是先归一化，再 `gather`：

```python
# student_logits 对应整个词表，形状为 [B, T, V]。
# teacher_topk_ids 是每个位置老师选中的 ID，形状为 [B, T, K]。
student_log_probs = student_logits.float().log_softmax(dim=-1)
student_selected_logp = student_log_probs.gather(
    dim=-1, index=teacher_topk_ids.long()
)  # 得到 [B, T, K]，与老师的 K 项一一对应。
```

**k 控制取几项，Teacher 返回的 token ID 控制取哪几项。** 这里选择的是词表候选；哪些序列位置参与 loss，则由 mask 决定，见[实现检查](#对照配置与实现检查)。按 ID 取 k 项用于监督，不代表模型只计算这 k 个 token 的 logits。

这里的概率必须保留它在**整个词表**中的含义。比如 Student 给“巴黎”的概率就是 0.20，不能把选出来的两项 `[0.20, 0.10]` 再除以 0.30，变成 `[2/3, 1/3]` 后仍当成原始概率。接下来 TA-OPD 要解决的问题，恰好就与这个区别有关。

### TA-OPD：比较候选与尾部的概率

#### 只看候选之间的比例会漏掉什么

沿用上面的例子。假设我们取出 top-2 后，对老师和学生分别重新归一化：

```text
Teacher：[0.60, 0.30] ÷ 0.90 = [2/3, 1/3]
Student：[0.20, 0.10] ÷ 0.30 = [2/3, 1/3]
```

这两张表完全一样。只比较它们，会觉得学生已经学得很好。

但看完整分布就知道不是这样：老师有 90% 的概率选择“巴黎或里昂”，学生只有 30%。学生把剩下 70% 的概率放在了另外三个城市上，而老师只放了 10%。

**两者在 top-2 内部的比例相同，不代表它们给 top-2 分配的总概率相同。** 对 top-k 重新归一化，会丢掉后面这条信息。

#### 把其余 token 合并成一个类别

TA-OPD 的 TA 是 Tail-Aware，意思是也关注尾部概率。尾部就是不在老师 top-k 集合中的所有 token。

它保留候选的原始概率，再把其余概率加起来，形成一个“其他”类别：

| 比较的类别     | Teacher | Student |
| -------------- | ------: | ------: |
| 巴黎           |    0.60 |    0.20 |
| 里昂           |    0.30 |    0.10 |
| 其他所有 token |    0.10 |    0.70 |

这时就能看到双方的差异了。TA-OPD 对这两张完整的三类概率表计算 reverse KL，让 Student 调整自己的分布。[TA-OPD 原论文](https://arxiv.org/abs/2608.14728)

所以，**top-k=64 的 TA-OPD，实际比较的是 64 个具体 token 加 1 个尾部类别，共 65 类。** 尾部只是计算 loss 时的合并类别，不需要修改 tokenizer。

它保留了尾部一共有多少概率，却不知道 Teacher 在尾部内部如何分配。因此它还不等于对整个词表做完整 KL。最终 loss 和求导方式见下文的[公式对照](#ta-opd-与-k1--pg-的-loss-和梯度对照)，数值代入过程见[附录](#ta-opd-将尾部合并后计算-reverse-kl)。

### k1 + PG：用采样 token 的概率形成反馈

#### 这次只评价学生实际选中的 token

TA-OPD 一次查看多个候选及尾部概率。k1 + policy gradient 则从另一个角度提供监督：

> 学生实际选了这个 token，老师有多认可这个选择？学生自己又有多认可？

仍然用那张城市概率表。假设 Student 这一次采样出了“巴黎”，我们只取这一个 token 的两个概率：

```text
Student 给“巴黎”的概率：0.20
Teacher 给“巴黎”的概率：0.60
```

把 Teacher 概率与 Student 概率的比值取对数，作为反馈：

$$
r=\log\frac{0.60}{0.20}=\log 3\approx 1.099
$$

这是正反馈：老师比学生更偏好这个选择，训练会倾向于提高学生在相同上下文下选择“巴黎”的概率。

如果 Student 采样出的其实是“伦敦”，则得到：

$$
r=\log\frac{0.04}{0.40}=\log 0.1\approx -2.303
$$

这是负反馈：学生给这个选择的概率比老师高，训练会倾向于压低它。

这些反馈来自 Teacher 与 Student 的概率比，不是 verifier 判断的任务对错。参数共享、batch 中的其他样本和实际优化器也会影响最终更新，不能保证每一个单独位置都按这个方向精确变化。

#### k1 和 policy gradient 分别负责什么

用 $p$ 表示 Student 概率，$q$ 表示 Teacher 概率，$a$ 表示学生实际采样的 token。这里的 k1 定义为：

$$
k_1(a)=\log p(a)-\log q(a)
$$

前面使用的反馈就是它的相反数：$r(a)=-k_1(a)$。

**k1 是一种 KL 采样估计量的名称，与 top-k 的 k 无关，更不等于 top-k=1。** top-k=1 取的是老师概率最高的 token；k1 评价的是学生实际采样的 token，这两个 token 可以完全不同。

Policy gradient 负责利用这个反馈更新学生。下面先讨论采样分布与当前学生分布一致的基本情形，暂不加入旧策略概率比或 PPO 裁剪。最简形式可以写成：

```python
# 两个 logprob 都对应 Student 实际采样的 token，形状为 [B, T]。
# 先形成反馈，再把反馈当作固定权重使用。
reward = (teacher_action_logp - student_action_logp).detach()
per_token_loss = -reward * student_action_logp

# 只在有效 assistant token 上求平均。
loss = (per_token_loss * mask).sum() / mask.sum().clamp_min(1)
```

注意这里有 `detach()`。我们用老师的评价给学生动作的 logprob 加权，而不是直接把 `student_logprob - teacher_logprob` 当成普通 loss 反传。后者的 Teacher 项是常数，求导后就消失了，无法起到这里期望的指导作用。完整解释见[附录中的 k1 梯度推导](#k1-的期望和策略梯度)。

实际框架还可能使用 PPO 风格的概率比和裁剪。上面只展示最基本的更新关系，不是可直接启动的训练脚本。[verl 的 PG OPD 说明](https://verl.readthedocs.io/en/latest/algo/opd.html)

### TA-OPD 与 k1 + PG 的 loss 和梯度对照

前面解释了两种方法各自怎么学。这里把**真正用于反向传播的 loss**放到一起，避免把 k1、反馈和训练 loss 混为一谈。

以下固定一个前缀、一个预测位置，省略条件符号。$p_\theta(v)$ 是学生概率，$q(v)$ 是冻结的老师概率，$S$ 是老师选出的 top-k 集合，$a$ 是学生实际采样的 token。尾部概率为：

$$
p_{\mathrm{tail}}=1-\sum_{v\in S}p_\theta(v),\qquad
q_{\mathrm{tail}}=1-\sum_{v\in S}q(v)
$$

**TA-OPD：直接对候选与尾部组成的分布计算 reverse KL。**

$$
\boxed{
\ell_{\mathrm{TA}}=
\sum_{v\in S}p_\theta(v)\log\frac{p_\theta(v)}{q(v)}
+p_{\mathrm{tail}}\log\frac{p_{\mathrm{tail}}}{q_{\mathrm{tail}}}
}
$$

学生概率直接参与求导，包括前面的权重 $p_\theta(v)$、对数中的学生概率，以及由它们计算出的尾部概率；这些学生项应保留完整梯度，老师分布则保持冻结。沿用 top-2 城市例子，双方的“巴黎、里昂、尾部”概率分别是 `[0.2, 0.1, 0.7]` 和 `[0.6, 0.3, 0.1]`，得到 $\ell_{\mathrm{TA}}\approx 1.0326$，代入过程见[附录](#ta-opd-将尾部合并后计算-reverse-kl)。

**k1 + PG：先计算反馈，再用固定反馈给动作 logprob 加权。**

$$
k_1(a)=\log p_\theta(a)-\log q(a),\qquad
r(a)=-k_1(a)
$$

$$
\boxed{
\ell_{\mathrm{PG}}=-\operatorname{stopgrad}\bigl(r(a)\bigr)\log p_\theta(a)
}
$$

反馈 $r$ 不是最终训练 loss。`stopgrad` 对应代码中的 `detach()`：反馈中的学生概率不参与求导，只通过后面那个动作 logprob 反向传播。

例如学生采到“伦敦”，$p_\theta(a)=0.40$、$q(a)=0.04$，则 $r\approx-2.303$。在这次反向传播中，把反馈固定后：

$$
\ell_{\mathrm{PG}}\approx 2.303\log p_\theta(\text{伦敦}),\qquad
\nabla_\theta\ell_{\mathrm{PG}}\approx
2.303\nabla_\theta\log p_\theta(\text{伦敦})
$$

梯度下降沿着降低这个动作 logprob 的方向更新；正反馈则给出相反方向。实际 batch 和共享参数对最终更新的影响，仍然遵循前文的限制。

| 比较点                                          | 本文的 TA-OPD 示例                 | 最基本的 k1 + PG                      |
| ----------------------------------------------- | ---------------------------------- | ------------------------------------- |
| 每个位置读取哪些监督                            | top-k 候选及尾部概率               | 实际采样 token 的老师概率             |
| 如何求梯度                                      | 直接对合并后分布的 reverse KL 求导 | 固定反馈，只对外面的动作 logprob 求导 |
| 固定前缀下，loss 是否直接依赖这次采到哪个 token | 不依赖；采样结果会决定后续前缀     | 依赖采样出的 token                    |
| 主要近似来自哪里                                | 合并尾部，丢掉尾部内部的分布差异   | 用采样动作估计梯度                    |

**这不是同一个 loss 的两种代码写法。** 在固定前缀、动作确实采自当前学生分布等条件下，基本 k1 + PG 的期望梯度对应完整词表 reverse KL 的梯度；TA-OPD 直接优化的是合并尾部后的 reverse KL，有限 top-k 下一般不等于完整词表 KL。推导与适用条件见[附录](#k1-的期望和策略梯度)。

还有两点容易误读：PG 的 surrogate loss 可以为负，不能把其数值当作 KL 距离与 TA-OPD 比大小；“只取一个 token”指监督读取方式，softmax 归一化和共享参数仍会影响其他 token 的概率。

两种方法最终都要把有效位置的 loss 聚合。例如按有效 token 平均：

$$
L=\frac{\sum_{b,t}m_{b,t}\ell_{b,t}}{\sum_{b,t}m_{b,t}}
$$

其中 $b$ 是样本索引，$t$ 是位置，$m$ 是有效 token mask；实现需要处理没有有效 token 的 batch。**两种方法的核心区别是 $\ell_{b,t}$ 怎么构造，token mean、turn mean 则是如何聚合的另一层选择。**

## 错误轨迹中能学到什么

**错误前缀确实会影响老师。老师给出的条件概率，不等于对当前步骤客观正确性的判定。** 它回答的是“给定问题和学生已经写出的内容，下一 token 应该是什么”。

沿用前面的算术题，学生可能写成：

```text
题目：3 + 2 × 4
学生：先算 3 + 2 = 5，再算 5 × 4 = 20，所以答案是 20。
```

在刚开始选择计算顺序时，老师可能更倾向先算乘法；但看到学生已经推导出 `5 × 4 = 20`，老师也可能认为最后接 `20` 很自然。**错误开始的位置可能收到纠正信号，顺着错误继续推导的位置却未必。** Thinking Machines 的[真实轨迹示例](https://thinkingmachines.ai/blog/on-policy-distillation/#illustration)也展示了这种现象：把推理带偏的部分受到惩罚，最终错误答案却没有，因为它在已有推导下很容易预测。

这说明监督有局限，但不表示 OPD 没有意义。它仍然能做两件有价值的事：

1. **减少最初的错误。** 训练会计算前面那些位置的 loss。预测早期 token 时，causal mask 挡住了后面的内容，所以后文犯了再多错误，也不会反过来污染这个位置的预测。如果老师在当时的前缀下更偏好正确选择，学生就有机会学到。
2. **学习错误之后如何继续。** 如果老师看到错误前缀后，倾向于接“等等，应该先算乘法”，学生就有机会学到检查、回退和修正。前提是老师本身具有这种能力；如果老师也顺着错误续写，OPD 不会自动产生可靠的纠错监督。

**因此，不能简单说“越长越难，OPD 越没用”。长轨迹更容易偏离老师示范过的路径，更需要学习学生实际会遇到的上下文；但严重跑偏的历史也可能降低老师监督的质量。**效果取决于学生走到了什么状态，以及老师在这些状态下是否仍能提供有用指导，不能只看长度。

对于 Agent，老师觉得一个工具调用是自然的下一步，也不等于它一定能让任务成功。蒸馏 loss 衡量与老师的接近程度；测试通过率和环境成功率仍要独立检查。

## 生成、评分和更新如何安排

理解了训练信号后，再看生成、评分与更新如何安排。算法需要哪些信息，与系统在什么时候计算这些信息，是两个层面。

### 先看同步流程

最容易理解和验证的安排，是先采样一批，再训练并同步权重：

```text
学生用 θ₀ 生成一批回答 → 老师评分 → 学生训练
                                      ↓
                         新权重同步到生成侧 → 下一批
```

这里“生成完成”是到 EOS、停止条件或长度上限，不保证题目做对，也不保证 Agent 任务成功结束。“一批 rollout 后训练”也不要求恰好执行一次 optimizer step，具体还取决于 minibatch、梯度累积和样本复用设置。

### 为什么通常生成后再做一次训练前向

回头看，学生确实做了两种不同的工作：

| 阶段             | 学生在做什么                       | 产出什么                                        |
| ---------------- | ---------------------------------- | ----------------------------------------------- |
| rollout          | 从问题开始，逐 token 采样          | 一份确定的回答，以及算法需要的采样信息          |
| training forward | 读取固定的问题与回答，重新计算预测 | 用来计算 loss、能够反向传播的 logits 或 logprob |

**学生在 rollout 时就已经计算了概率，否则无法采样下一个 token。** 这些 logprob 可以按需保存，用于构造反馈或计算重要性采样比。但 rollout 通常不保留训练计算图：保存一个概率数值，不等于保留了它与模型参数之间的求导关系。因此训练时通常重新前向，获取能反向传播的预测。**第二次前向是在计算“学生给这份固定输入怎样的概率”，不是让学生重新答一次题。**

理论上也可以在生成时保留计算图，再用它反向传播；但这会增加生成期间保存中间激活的显存开销，而且生成必须逐 token 推进。先生成、再对固定序列并行前向，更方便把推理引擎与训练引擎分开调度，利用批处理提高吞吐。这是常见的工程安排，不是 OPD 必须前向两次的定义。

### 两次前向的概率会不会不同

**生成答案的随机性来自采样，不意味着同一个前缀的概率分布每算一次就随机改变。** 例如 rollout 时，“问题 + 首都是”对应的学生概率是“巴黎 0.20、里昂 0.10、伦敦 0.40、其他 0.30”。从中抽到“伦敦”，不会把它的概率变成 1，也不会修改模型参数。

第二次前向虽然输入了完整回答，但在预测“伦敦”的位置，causal mask 仍然只允许看到“问题 + 首都是”。如果参数、输入前缀、位置与计算设置一致，并且没有 dropout 等随机因素，数学上的概率分布应当相同。开启梯度记录本身不会改变概率值，它保留的是概率与参数之间的求导关系。

实际实现中，两次结果可能因以下原因不同：

| 原因                 | 具体影响                                                                                 |
| -------------------- | ---------------------------------------------------------------------------------------- |
| 参数已经更新         | 异步训练或复用同一批数据做多次更新时，训练侧可能已不是采样时的模型。                     |
| 采样分布经过变换     | temperature、top-p、top-k 等改变实际抽样分布；训练若使用原始 softmax，就不是同一种概率。 |
| 运行模式不同         | rollout 关闭 dropout、训练开启 dropout 时，两次输出可能不同。                            |
| 数值实现不同         | 精度、量化、算子和计算顺序可能造成偏差。                                                 |
| 输入或预测位置不一致 | token、attention mask、position ID 或 shift 对齐错误，会导致比较的条件概率不同。         |

这里的采样 top-k 用于限制抽样候选，与老师返回 top-k 概率作为蒸馏监督，是两种用途。比较两次 logprob 前，也要确认记录的是原始模型概率还是经过采样变换后的概率。

对于 TA-OPD 这样的直接蒸馏，loss 比较的是固定前缀下**当前学生**与老师的分布，不要求当前概率等于保存的 rollout 概率；但前缀若来自很旧的学生，训练数据就偏离当前策略的状态分布。对于 k1 + PG，采样分布还直接关系到梯度估计，不能把旧策略或变换后的分布采出的动作无条件当成当前策略样本；应按具体算法考虑重要性采样、裁剪和样本陈旧度等处理。[verl 的 rollout correction 说明](https://verl.readthedocs.io/en/latest/algo/rollout_corr.html)

最简单的同步情形是：$\theta_0$ rollout → 保持条件一致，$\theta_0$ 重新前向得到基本相同的概率并保留计算图 → 执行更新得到 $\theta_1$。**重新前向本身不是概率变化的原因，参数、输入或计算方式的变化才是。**

### 分块评分不等于分块更新

**“分块”回答的是每次处理多少数据；“何时更新”回答的是多久改变一次学生。** 分块获取老师概率，本身不意味着更新学生参数。

**老师也不必等整条回答结束才评分。** 学生写到“首都是”时，老师就可以针对这个前缀计算下一 token 的概率；随后老师跟随学生实际选出的 token，继续评价后续位置。可以逐 token 或分块执行，只是频繁的小请求和同步可能影响效率。前面的完整 rollout 流程便于说明和批量计算，不意味着 OPD 禁止边生成边获取监督。

假设把一份回答按每 256 个 token 分成三块，可以这样安排：

```text
学生参数保持为 θ₀：
生成第 1 块 → 交给老师评分
生成第 2 块 → 交给老师评分
生成第 3 块 → 交给老师评分

收集训练数据 → 学生训练前向与反向传播 → 更新参数
```

资源允许时，老师评价第 1 块，学生可以同时生成第 2 块。老师评价第 2 块时，仍然要看到问题和第 1 块；可以重新输入前缀，或在支持的实现中使用老师自己的 KV cache。**分块不是丢弃前文，也不会消除错误前缀的影响。**

训练端还可以按 micro-batch 累计梯度，之后才执行 `optimizer.step()`。一次 backward 不等于一次参数更新。这里按样本拆 micro-batch，也不要与沿一条序列切块混淆；沿序列切块训练还需要处理前缀上下文和梯度，不能随意截断。

### 异步让不同批次的工作重叠

同步流程中，各阶段会等待前面的工作完成。异步可以让训练侧处理批次 A、教师侧评价批次 B、生成侧生成批次 C。训练侧再按策略把新权重同步给生成侧；生成和训练使用的参数可能暂时不同。

**异步训练不等于同一条回答每生成一块就更新一次。** 例如 [TRL Async Distillation](https://huggingface.co/docs/trl/main/en/async_distillation_trainer) 文档中的 LoRA 方案：保留多个 adapter 版本，让已启动的 rollout 使用原版本生成完，避免中途换模型。

截至 2026-10-26 核对的下列公开示例，常见组织方式是**按样本或批次收集 rollout，再做训练更新；提高吞吐时，让不同样本或批次的生成、评分、训练重叠。** 这是对这些实现的归纳，不是整个行业的使用比例统计。

| 实现                                                                                                   | 生成与更新如何安排                                                                                                                       |
| ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| [TRL GKDTrainer 源码](https://github.com/huggingface/trl/blob/main/trl/experimental/gkd/gkd_trainer.py) | on-policy 分支先调用 `generate` 取得序列，再进入训练前向与反向；不是在这次生成的每个小块之间更新。                                     |
| [verl 异步 OPD recipe](https://verl.readthedocs.io/en/latest/advance/async-on-policy-distill.html)      | 让不同批次的生成、教师评分与训练重叠，通过权重同步推进生成侧，代价是部分样本落后于训练参数版本。                                         |
| [TRL Async Distillation](https://huggingface.co/docs/trl/main/en/async_distillation_trainer)            | 后台生成 completion 并获取教师评分，训练侧从队列取数据更新；`weight_sync_steps` 控制同步频率，`max_staleness` 限制样本落后的版本数。 |

### 补充：部分 rollout 与中途更新

部分 rollout 可以是“只生成一段就用于训练，下一轮重新采样”，不一定要继续原来的回答。只依赖当前前缀的 token 级监督允许这样做；若还需要最终任务奖励，则要另行处理终局信息。[部分 rollout 的原理说明](https://thinkingmachines.ai/blog/on-policy-distillation/#loss-function-reverse-kl)

也可以设计为 `θ₀ 生成第 1 块 → 更新为 θ₁ → θ₁ 接着生成第 2 块`，但这已经改变了采样流程：同一条轨迹混用了不同版本的学生，旧块不能当作全部由最新策略生成。更新也不会改写旧块中的错误；若要让新模型正确处理已有前缀，通常需要重新计算前缀 KV cache，不能把旧参数算出的缓存直接当作新模型缓存。

就学习和小规模验证而言，可以先实现“采样一批 → 老师评分 → 学生训练 → 同步权重 → 下一批”的同步流程，再根据实际瓶颈考虑异步。看代码时分别找生成停止条件、`optimizer.step()` 和权重同步位置，就能判断它采用的是哪一种安排。

## 对照配置与实现检查

### 对照两种配置

下面把两种训练信号对应到配置字段。这里只说明本文示例的语义，具体字段是否可用还要看训练代码版本。

| 参数                    | TA-OPD 示例                     | k1 + PG 示例               |
| ----------------------- | ------------------------------- | -------------------------- |
| `loss_mode`           | `taopd_reverse_kl_topk`       | `k1`                     |
| `topk`                | `64`                          | 不使用 top-k 监督          |
| `use_policy_gradient` | `False`，直接对分布损失求梯度 | `True`，把负 k1 作为反馈 |
| `use_task_rewards`    | `False`，只使用蒸馏信号       | `False`，只使用蒸馏信号  |

`use_policy_gradient=False` 表示直接对蒸馏损失求梯度，不改变回答由 Student 生成这一点。

`use_task_rewards=False` 表示不把任务结果奖励混入更新，Teacher 的概率仍然提供蒸馏信号。效果评估的边界见[错误轨迹中的学习价值](#错误轨迹中能学到什么)。

### 词表、位置、mask 与 loss 聚合

- **Teacher 和 Student 的 ID 要表达同一个 token。** 直接按 ID 取概率，要求两边的词表映射兼容；只看词表大小相同还不够。特殊 token 和实际编码结果也需要核对。
- **预测位置要对齐。** 在预测 `y₂` 时，两边都应该看到“问题 + `y₁`”。常见训练代码用 `logits[:, :-1]` 对齐 `input_ids[:, 1:]`；Teacher 服务若已经做了对齐，不要再错移一次。
- **只训练应该由模型生成的部分。** prompt、padding 和工具返回通常要 mask 掉。代码示意中的分母保护只避免除零，不能代替对空有效样本的检查。
- **尾部概率需要数值稳定的计算。** 当 top-k 概率和很接近 1 时，直接做 `1 - mass` 容易损失精度；可参考[论文附录 D.2 的 log-space 实现](https://arxiv.org/html/2608.14728v1)。
- **按 token 平均和按轮平均是另一个选择。** 假设一轮生成 100 个有效 token，另一轮生成 10 个，token mean 中前者的总权重是后者的 10 倍；先在每轮内平均、再做 turn mean，则两轮总权重相同。框架具体按样本还是全 batch 聚合，需要查看实现。这与使用 TA-OPD 还是 k1 并不是同一个问题。

### 只取 64 项为什么仍可能占很多显存

用 $z_i$ 表示 Student 对 token $i$ 的 logit，$V$ 表示整个词表，$S$ 表示 Teacher 选出的 top-k ID 集合。Student 选中项的 logprob 是：

$$
\log p(i)=z_i-\operatorname{logsumexp}_{j\in V}(z_j),\qquad i\in S
$$

虽然只需要返回 64 项，但分母仍然包含整个词表。可以用下面的等价计算，避免保存完整的 log-softmax 输出：

```python
# 仍然需要计算全词表的归一化项。
log_z = student_logits.float().logsumexp(dim=-1, keepdim=True)
selected_logits = student_logits.gather(-1, teacher_topk_ids.long()).float()
student_selected_logp = selected_logits - log_z
```

这个示意片段本身仍会创建完整 FP32 临时张量。实际省显存还要结合分块或融合计算，并关注反向传播保存了什么。

因此，top-k 主要减少 Teacher 监督的传输、存储和后续比较开销；如果 Student 仍然物化完整词表 logits，那个张量仍是 `[B,T,V]`，不会因为 k=64 自动变成 `[B,T,64]`。

## 附录 A：公式与梯度

正文已经说明实际过程。这里补全 KL 与梯度关系，便于读论文和源码时对照。

### 完整 KL 比较的是整个词表

固定某一个上下文 $s$，记 $p(v)=p_\theta(v\mid s)$ 为 Student 概率，$q(v)=q(v\mid s)$ 为冻结的 Teacher 概率，$V$ 为词表。本文采用的方向约定是：

$$
\underbrace{D_{\mathrm{KL}}(q\Vert p)}_{\text{forward KL}}
=\sum_{v\in V}q(v)\log\frac{q(v)}{p(v)}
$$

$$
\underbrace{D_{\mathrm{KL}}(p\Vert q)}_{\text{reverse KL}}
=\sum_{v\in V}p(v)\log\frac{p(v)}{q(v)}
$$

两者在完整分布相同时为 0。方向的区别体现在用谁的概率加权，读其他资料时需要同时核对符号定义。

### TA-OPD 将尾部合并后计算 reverse KL

令 $S=\mathrm{TopK}(q,k)$ 为老师选中的 token 集合，定义：

$$
p_{\mathrm{tail}}=1-\sum_{i\in S}p(i),\qquad
q_{\mathrm{tail}}=1-\sum_{i\in S}q(i)
$$

则：

$$
\ell_{\mathrm{TA}}=
\sum_{i\in S}p(i)\log\frac{p(i)}{q(i)}
+p_{\mathrm{tail}}\log\frac{p_{\mathrm{tail}}}{q_{\mathrm{tail}}}
$$

城市例子中的结果为：

$$
\ell_{\mathrm{TA}}
=0.2\log\frac{0.2}{0.6}
+0.1\log\frac{0.1}{0.3}
+0.7\log\frac{0.7}{0.1}
\approx 1.0326
$$

如果只比较重新归一化的 top-2，两边都是 $[2/3,1/3]$，KL 则为 0。这正是尾部项补回的信息。

### k1 的期望和策略梯度

当 $a\sim p$ 时，k1 的期望为：

$$
\mathbb{E}_{a\sim p}[\log p(a)-\log q(a)]
=D_{\mathrm{KL}}(p\Vert q)
$$

单个 k1 值可以为负，例如学生采样“巴黎”时为 $\log(1/3)$；非负的是上式的完整期望，不要求每个样本都非负。

容易混淆的是：**一个数值估计是无偏的，不代表把采样结果固定下来直接求导，就会得到正确的梯度估计。** 固定 $a$ 后，朴素求导只得到：

$$
\nabla_\theta\left[\log p_\theta(a)-\log q(a)\right]
=\nabla_\theta\log p_\theta(a)
$$

而固定上下文上的完整 reverse KL 的梯度是：

$$
\begin{aligned}
\nabla_\theta D_{\mathrm{KL}}(p_\theta\Vert q)
&=\sum_a \nabla_\theta p_\theta(a)
\left(\log p_\theta(a)-\log q(a)+1\right)\\
&=\mathbb{E}_{a\sim p_\theta}\left[
\left(\log p_\theta(a)-\log q(a)\right)
\nabla_\theta\log p_\theta(a)
\right].
\end{aligned}
$$

第二行用到了 $\sum_a\nabla p_\theta(a)=\nabla 1=0$，所以额外的 $+1$ 项消失。Teacher 的信息作为一个权重，乘在 Student 的 logprob 梯度上。

因此可以使用如下 surrogate loss：

$$
\ell_{\mathrm{PG}}
=-\underbrace{\operatorname{stopgrad}
\left[\log q(a)-\log p_\theta(a)\right]}_{\text{固定反馈}}
\log p_\theta(a)
$$

这对应前文代码中的 `detach()`。在采样分布确实等于当前 $p_\theta$ 时，它的期望梯度与上述固定上下文 KL 的梯度一致：

$$
\mathbb{E}_{a\sim p_\theta}
\left[\nabla_\theta\ell_{\mathrm{PG}}(a)\right]
=\nabla_\theta D_{\mathrm{KL}}(p_\theta\Vert q)
$$

这是梯度期望的关系，不表示 surrogate loss 的数值等于 KL，也不表示有限 top-k 的 TA-OPD 与它优化完全相同的分布差异。

这里有两个边界：第一，推导固定了上下文，没有包含动作改变后续状态分布带来的完整轨迹梯度；第二，复用旧 rollout、多次更新，或改变采样温度、做 top-p 截断后，实际采样分布可能已经不同，需要另行考虑概率比等修正。
